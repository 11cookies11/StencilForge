# 开口规则工作台实现说明

## 本次目标

把开口规则从“只在 UI 里占位”推进到“能参与生成、能导入导出、能按规则匹配”。

本轮先按用户确认的简化方向推进：

- 暂时不考虑 `Top / Bottom`
- 规则按 `package` 和 `padType` 匹配
- 匹配结果直接参与开口生成

## 已实现内容

### 1. 统一规则命名，移除 `Top / Bottom`

规则定义、规则描述、规则编辑器都不再把 `layer` 作为规则匹配字段。

这样做的原因：

- 先把规则模型收窄，减少用户理解成本
- 避免一开始就把 PCB 正反面维度引入到工作台里
- 让规则优先聚焦在封装和焊盘类型上

### 2. 规则按 `package + padType` 进行匹配

后端工作台现在会根据当前工作台状态，选择最合适的规则：

- 优先看 `package`
- 再看 `padType`
- 支持 `Any` 作为通配
- 支持规则优先级和匹配具体度排序

匹配逻辑已经接入生成流程，选中的规则会影响最终开口计算，而不只是前端预览。

### 3. 规则结果会参与生成

当前工作台里的匹配结果不再只是展示态，而会进入生成逻辑：

- `delta` 规则会影响开口偏移
- `scale` 规则会影响开口缩放
- 规则效果在导出前就会生效

### 4. 规则导入 / 导出已接后端

规则工作台的导入 / 导出现在不是前端假按钮：

- 导入会经过后端校验
- 导出会输出当前工作台状态
- 兼容旧字段别名，但会忽略不再使用的字段

### 5. 回归测试已补

本轮补了几类回归：

- 去掉 `Top / Bottom` 后，描述文本不会再带层信息
- `package + padType` 匹配会优先选中更具体的规则
- 规则效果会真实影响生成结果
- 旧格式导入仍能兼容

## 当前状态

现在这条链路已经完成到“可用版”：

- UI 能编辑和显示规则
- 后端能读写工作台状态
- 规则能影响生成
- 导入导出可往返

下一步如果继续推进，最值得做的是：

- 细化规则如何分组到不同焊盘
- 继续完善规则与实际生成几何的映射
- 把更多结果摘要收敛成更稳定的 UI 结构
