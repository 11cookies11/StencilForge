# 软件代码调整计划

## 目标

把 StencilForge 的代码整理成更容易阅读、维护和扩展的状态，同时保持现有功能稳定。

## 调整原则

- 优先修复影响发布、运行和数据一致性的高风险问题。
- 先统一数据和入口，再整理 UI 和表现层。
- 小步提交，每一步都能单独验证。
- 所有改动都以 `docs/code-spec.md` 作为代码规范依据。

## 第一阶段：修复阻塞问题

- 修复不存在的入口点引用，例如 `setup.py` 里的 `stencilforge-ui-vtk`。
- 让配置序列化完整往返，避免 UI 保存时丢失隐藏字段。
- 检查并修正打包脚本、清单文件和源码之间的引用一致性。
- 清理乱码注释、乱码字符串和明显的历史遗留噪音。

## 第二阶段：统一配置层

- 以 `StencilConfig` 作为唯一配置模型。
- 为配置建立明确的读入、更新、保存路径。
- 补全 `to_dict()` 或等效序列化逻辑，保证全量输出。
- 统一 UI、CLI、打包脚本对配置字段的使用方式。
- 补充配置相关回归测试。

## 第三阶段：整理后端结构

- 将 `ui_app.py` 中职责混杂的逻辑拆分为更小的辅助函数。
- 保持 UI、文件扫描、任务调度、预览和日志逻辑分层。
- 让 `pipeline/`、`geometry/`、`config.py` 的职责边界更清楚。
- 减少跨层直接依赖，避免 UI 直接承载业务规则。

## 第四阶段：整理前端结构

- 拆分过大的 Vue 单文件组件。
- 将页面、区块、控件、图标等拆开。
- 抽取重复样式和重复交互逻辑。
- 让主界面更易扫描，保持工具型界面风格一致。
- 保证所有文案走 i18n。

## 第五阶段：统一构建与打包

- 统一主程序图标、商店图标、MSIX 图标和 README 展示图。
- 检查 `build_msix.ps1`、`AppxManifest.xml`、Installer 脚本之间的配合。
- 确保打包产物与源码品牌一致。
- 为发布链路保留本地验证步骤。

## 第六阶段：补齐测试与验证

- 为配置、入口、打包和主流程增加或完善回归测试。
- 保持 Python 侧 `compileall`、`pytest` 能跑通。
- 保持前端构建、i18n 检查和单元测试通过。
- 对会影响发布的改动增加明确的验证步骤。

## 推荐执行顺序

1. 修复阻塞问题。
2. 统一配置层。
3. 整理 `ui_app.py` 和相关后端模块。
4. 整理 Vue 前端结构。
5. 收束打包与品牌资源。
6. 补齐测试并做一次整体回归。

## 预期结果

- 代码更容易读。
- 配置不会在保存或更新时丢字段。
- 入口、脚本和打包配置不会互相打架。
- 前后端结构更清楚，后续加功能更稳。
- 发布前的风险更容易被自动化检查拦住。
